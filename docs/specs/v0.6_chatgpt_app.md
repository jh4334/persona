# v0.6 기획 — ChatGPT 앱 "교실 무대" (버셀 + 슈파베이스)

## 목표

교사가 **자기 ChatGPT 계정으로**(별도 결제·API 키 없이) 도트 교실 수업 시뮬레이션을 실행하게 한다. 배포는 심사가 필요 없는 **개발자 모드 URL 공유**로 시작하고, 사용자가 늘면 앱 디렉터리 심사 제출로 전환한다.

## 아키텍처

```
사용자의 ChatGPT (Plus/Pro)
 │  모델 = 무대 감독 + 학생 배우      ← 구독 한도에서 차감, 우리 비용 0
 │
 │  MCP (도구 호출)
 ▼
MCP 서버 — 버셀 (TypeScript, 서버리스)
 │  · 규칙 엔진: 명령 파싱, 게이지 경계, 국면, 돌발 카드, 리포트 틀
 │  · 도트 교실 UI 컴포넌트 서빙 (기존 프론트 이식)
 ▼
슈파베이스 (Postgres + Auth + Storage)
 · 학급/페르소나, 세션 상태, 전사, 리포트
```

**역할 분리 원칙** — 기존 무대 감독 패턴을 뒤집는다: 로컬판에서는 우리가 LLM을 호출했지만, 여기서는 **ChatGPT가 주체**이고 우리 서버는 "규칙과 기억"만 담당한다. 즉 게이지 산식·페르소나 근거·연기 원칙은 도구 설명과 도구 응답에 실어 ChatGPT에게 지시하고, 서버 자체는 LLM을 전혀 호출하지 않는다(그래서 운영비 0).

## MCP 도구 설계 (7종)

| 도구 | 입력 | 응답 (ChatGPT가 받는 것) |
|---|---|---|
| `list_classrooms` | — | 사용자의 학급 목록 |
| `create_classroom` | 학급 JSON (v2.1 스키마) | 검증 결과 + 학급 id |
| `start_session` | classroom_id, 수업안 텍스트 | session_id + 전체 페르소나 + 초기 상태 + **연기 지침**(미화 금지 등) |
| `record_turn` | session_id, 교사 입력, ChatGPT가 연기한 결과(발화·상태 변화) | 검증·저장 후 다음 턴 참고사항 (게이지 경계 위반 교정, 발언 형평성 힌트, 경과 시간) |
| `get_state` | session_id | 현재 게이지 표 + 도트 교실 **컴포넌트 렌더** |
| `trigger_incident` | session_id, 카드명? | 돌발 카드 내용 |
| `end_session` | session_id | 통계(형평성·지목 분포) + 리포트 틀 → ChatGPT가 리포트 완성, 서버에 저장 |

핵심 설계: **`record_turn`이 심판 역할**을 한다. ChatGPT가 자유 연기하되, 서버가 게이지 급변·페르소나 붕괴(예: 최민준 이해도가 근거 없이 30→90)를 감지하면 응답으로 교정 지시를 돌려준다. 이것이 커스텀 GPT(순수 기억 의존)와의 결정적 차이.

## 도트 교실 컴포넌트

- Apps SDK 컴포넌트(iframe)로 기존 `web/static/` 캔버스 렌더러를 이식. 바닐라 JS·의존성 0·에셋 포함이라 이식성 좋음
- 데이터는 `get_state` 응답의 구조화 페이로드로 주입 (기존 state_snapshot 형태 재사용)
- 상호작용 축소: 클릭=학생 카드 열기만. 명령 입력은 ChatGPT 채팅이 담당

## 슈파베이스 스키마 (초안)

```sql
users        (id, chatgpt_sub, created_at)              -- MCP 인증 주체
classrooms   (id, user_id, name, grade, data jsonb)     -- v2.1 페르소나 JSON
sessions     (id, user_id, classroom_id, lesson_text, phase, minute, turn,
              states jsonb, groups jsonb, status, created_at)
transcripts  (id, session_id, seq, actor, kind, content, meta jsonb)
reports      (id, session_id, markdown, stats jsonb, created_at)
```

- RLS(Row Level Security)로 사용자별 격리. 인증은 MCP OAuth → 슈파베이스 JWT 매핑
- 개인정보: 학급 데이터에 실명 금지 안내를 create_classroom 검증 단계에서 노출

## 배포 단계

1. **알파(심사 없음)**: 버셀 배포 → 개발자 모드 안내문과 MCP URL 공유 → 본인+동료 교사 사용
2. **베타**: 피드백 반영, 사용 안내 페이지(버셀 정적) 추가
3. **공개(선택)**: 앱 디렉터리 심사 제출

## 작업 분해 (Opus 위임 단위)

| # | 작업 | 산출물 | 크기 |
|---|---|---|---|
| 1 | MCP 서버 골격 + 도구 7종 (TS, 버셀) | `apps/chatgpt/` 새 디렉터리 | 대 |
| 2 | 게이지 심판 로직 TS 포팅 (mock 백엔드 규칙 재사용) | rules.ts | 중 |
| 3 | 슈파베이스 스키마 + RLS + 클라이언트 | schema.sql, db.ts | 중 |
| 4 | 도트 교실 컴포넌트 이식 | component/ | 중 |
| 5 | 통합 테스트(개발자 모드 실기기) + 사용 안내문 | docs | 소 |

순서: 1→2→3 병렬 가능, 4는 1 이후, 5는 사용자 실기기 필요(ChatGPT 로그인). 착수 전 확정할 것: 슈파베이스 프로젝트 생성(사용자 계정), 버셀 프로젝트 연결(사용자 GitHub 계정).
