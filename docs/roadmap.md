# 개발 로드맵 — "교실 무대" 실시간 수업 시뮬레이션

## 최종 목표

> 학생 페르소나를 직접 입력하거나 이미 만들어진 페르소나 학생들을 **교실 무대로 데려와서**, 교사가 **실제로 수업을 진행하듯 상호작용**하면 학생들이 실시간으로 반응하는 시뮬레이션 프로그램.

지금 버전(v0.1)은 "수업 계획서를 주면 예측 리포트를 한 번에 뽑는" **일괄 예측 도구**입니다. 최종 목표는 교사가 한 마디씩 수업을 진행하고 학생들이 그때그때 반응하는 **인터랙티브 무대**입니다. 이 문서는 그 사이를 잇는 계획입니다.

```
[완료] v0.1  일괄 예측 리포트     : 수업안 → 학생별 예측 → 리포트
[완료] v0.2  페르소나 카탈로그    : 9그룹 102속성, 스키마 도구
─────────────────────────────────────────────────────────
[완료] v0.3  교실 무대 엔진 (터미널판) — stage/ 모듈, mock/anthropic 백엔드
[완료] v0.4  웹 UI — 보이는 교실 — 게더타운풍 도트 교실 (web/), 에셋 요청서
[완료] v0.5  살아있는 교실 — 모둠 대화·돌발 카드 6종·수업 분석 (A/B 비교·학기 누적은 미착수)
[기획완료] v0.6  ChatGPT 앱 — 각자 구독으로 쓰는 도트 교실 (docs/specs/v0.6_chatgpt_app.md)
[4단계] v1.0  배포판 (로컬 모델, 기관 배포)
```

## 핵심 설계: 교실 무대는 어떻게 돌아가는가

### 무대 감독(Director) 패턴 — 비용과 현실성의 핵심

교사가 한 마디 할 때마다 학생 12명을 전부 AI로 호출하면, 40분 수업(교사 발화 ~60회)에 호출이 700회를 넘고 비용이 감당되지 않습니다. 실제 교실에서도 교사의 모든 말에 12명 전원이 반응하지 않습니다. 그래서 **무대 감독**을 둡니다.

```
교사 입력 ("비란 두 수를 나눗셈으로 비교하는 거예요. 3 대 5처럼.")
   │
   ▼
① 무대 감독 (저비용 모델, 1회 호출)
   - 장면 해석: 지금 수업 국면은? 누구에게 영향이 가는 발화인가?
   - 전원 상태 갱신: 12명의 이해도·흥미·집중 게이지를 한 번에 조정
   - 배역 선정: 이번 턴에 "겉으로 드러나는 반응"을 할 학생 1~3명 선택
     (지목당한 학생은 무조건 포함, 손드는 학생, 딴짓하는 학생...)
   │
   ▼
② 선택된 학생 에이전트만 발화 생성 (고품질 모델, 1~3회 호출, 병렬)
   - 각 학생은 자기 페르소나 + 자기 상태 + 수업 전사(transcript)를 보고
     "그 학생답게" 말하거나 행동
   │
   ▼
③ 장면 출력
   💬 최민준: (고개를 숙이며) "……"
   💬 김하늘: "선생님, 그럼 5 대 3이랑 3 대 5랑 같은 거예요?"
   📊 [상태] 최민준 이해도↓ 집중↓ / 강도윤 집중↓ (설명 12분째)
```

턴당 호출 2~4회로 억제되어, 40분 수업 전체가 리포트 1회 생성과 비슷한 비용대에 들어옵니다.

### 상태 모델 — 학생은 게이지를 가진다

각 학생은 수업 내내 변하는 상태를 가집니다. 감독이 매 턴 갱신합니다.

| 게이지 | 의미 | 변화 요인 예 |
|---|---|---|
| 이해도 (0~100) | 현재 진도를 따라오고 있는가 | 설명 난이도, 개별 지도, 결손 누적 |
| 흥미 (0~100) | 지금 수업이 재미있는가 | 관심사 연결, 활동 유형, 반복 |
| 집중 (0~100) | 지금 딴짓 중인가 | 경과 시간, 주의집중 특성, 주변 소란 |
| 정서 | 위축/평온/들뜸/불안 … | 지목, 실패 경험, 칭찬 |

게이지는 **페르소나 속성의 함수**로 움직입니다. 주의집중_지속시간이 "5~15분"인 강도윤은 설명 15분째에 집중이 급락하고, 발표불안이 높은 윤지우는 지목당하는 순간 정서가 '불안'으로 바뀝니다. 이 규칙 자체를 감독 프롬프트에 넣어 일관성을 만듭니다.

### 수업 전사(Transcript) — 하나의 사실, 여러 관점

무대에서 일어난 모든 일(교사 발화, 학생 발화, 행동, 상태 변화)은 시간순 전사 한 벌로 기록됩니다.

- **학생 에이전트**가 발화할 때: 전사 중 "그 학생이 실제로 보고 들었을 부분"만 제공 (집중이 낮았던 구간은 "…딴생각을 하느라 놓쳤다"로 처리 — 현실성의 핵심)
- **수업 종료 후**: 전사 전체를 기존 리포트 파이프라인(v0.1)에 넣어 사후 분석 리포트 생성 → 기존 코드가 그대로 재활용됨
- **저장/재생**: 전사를 JSON으로 저장해 같은 수업을 다시 보거나, 중간부터 다른 전개로 분기 가능

### 교사가 할 수 있는 행동 (입력 문법)

| 행동 | 입력 예 | 무대에서 일어나는 일 |
|---|---|---|
| 전체 발화 | `비란 두 수를 나눗셈으로...` | 전원에게 전달, 감독이 반응자 선정 |
| 특정 학생 지목 | `@윤지우 3대 5에서 기준량이 뭘까?` | 해당 학생 반드시 발화 (페르소나에 따라 침묵도 "발화") |
| 판서/자료 제시 | `/판서 3 : 5 → 3/5 = 0.6` | 시각 자료로 기록, 시각형 학습자에게 가중 |
| 활동 지시 | `/활동 짝과 교실에서 비 찾기 3분` | 활동 국면 전환, 활동형 학생 게이지 상승 |
| 순회 지도 | `/순회 최민준` | 1:1 장면 — 해당 학생과 소대화 |
| 칭찬/주의 | `/칭찬 오하린` | 정서 게이지 반영 |
| 시간 경과 | `/시간 5분` | 활동 시간을 건너뛰고 결과 요약 |
| 상태 확인 | `/상태` | 전원 게이지 표 출력 (교사용 — 학생은 모름) |
| 종료 | `/종료` | 수업 마감 → 사후 리포트 생성 |

## 단계별 계획

### 1단계 (v0.3) — 교실 무대 엔진 + 터미널판 ⏱ 가장 중요

웹 화면 없이, 터미널에서 완전한 무대를 돌릴 수 있게 만드는 단계. 엔진이 완성되면 UI는 갈아끼우는 문제가 됩니다.

**만들 것**

| 모듈 | 역할 |
|---|---|
| `stage/state.py` | 학생 상태(게이지·정서), 교실 상태, 수업 국면 정의 |
| `stage/transcript.py` | 전사 기록·저장·관점 필터(학생이 본 것만 추출) |
| `stage/director.py` | 무대 감독 — 장면 해석, 전원 상태 갱신, 반응자 선정 (structured output) |
| `stage/student_agent.py` | 학생 발화 생성 — 페르소나+상태+관점 전사 → 대사/행동 |
| `stage/session.py` | 턴 루프 오케스트레이션, 교사 명령 파싱 |
| `stage/cli.py` | 터미널 UI (`python -m classroom_sim.stage`) |
| 사후 리포트 연결 | 전사 → 기존 report.py 파이프라인 |

**기술 결정**
- 감독: `claude-haiku-4-5` (턴마다 호출되므로 저비용 필수), 학생 발화: `claude-opus-5` 기본에 `--student-model`로 조정 가능
- 프롬프트 캐싱: 학급 페르소나 전체 + 수업 자료를 캐시 프리픽스로 고정, 전사만 뒤에 증분
- 전사 자동 요약: 전사가 길어지면(30턴+) 앞부분을 요약으로 접어 비용 유지

**완료 기준**: 샘플 학급으로 10턴 수업을 진행했을 때 ① 지목한 학생이 페르소나답게 답하고 ② 시간이 지나면 집중 낮은 학생부터 흐트러지며 ③ 종료 시 사후 리포트가 나온다. 턴당 평균 API 호출 ≤ 4회.

### 2단계 (v0.4) — 웹 UI "보이는 교실"

Streamlit(빠른 구현) 기반. 엔진은 1단계 것을 그대로 사용.

- **교실 화면**: 좌석 배치도에 학생 카드(이름, 게이지 막대, 현재 상태 이모지 🙋😴😟). 카드를 클릭하면 페르소나 상세
- **수업 진행 패널**: 채팅형 입력 + 명령 버튼(지목/판서/활동/순회), 전사 스크롤
- **페르소나 입력 UI** ← "직접 입력" 요구사항: 카탈로그 102속성을 폼으로 제공(그룹별 접기, 권장 척도는 선택지+자유입력), 학급 저장/불러오기, "무대로 데려오기" 버튼
- **학생 자동 생성**: "성취 상2 중6 하4, 다문화 1명 포함" → 카탈로그 기반으로 페르소나 초안 생성 (MatrAIx의 합성 생성 방식)
- 세션 저장/불러오기, 전사 다운로드

**완료 기준**: 코드를 모르는 교사가 브라우저만으로 학급 구성 → 수업 진행 → 리포트 확인까지 가능.

### 3단계 (v0.5) — 살아있는 교실

- **모둠 활동 모드**: 활동 지시 시 모둠별로 학생끼리 대화가 오가고(에이전트 간 상호작용), 교사는 순회하며 개입. 무임승차·주도권 다툼 같은 모둠 역학 재현
- **돌발 상황 카드**: 수업 중 무작위/선택 이벤트 주입 — 갈등 발생, 기기 고장, 방송 소음, 조퇴 요청 → 교실 대응 훈련
- **수업 분석 모드** (교생·연수용): 수업 종료 후 교사 행동 자체를 분석 — 발문 수준 분포(사실확인/절차/원리), 학생별 발언 기회 형평성, 대기 시간, 지목 편중. "수업 성찰 리포트"
- **수업안 A/B 비교**: 같은 학급·같은 단원을 두 설계안으로 자동 진행(교사 역할도 AI가 대행)해 나란히 비교
- 학기 모드 기초: 수업 결과가 페르소나에 누적(결손 심화/해소)

### 4단계 (v1.0) — 배포판

- **로컬 모델 백엔드**: Ollama/vLLM(OpenAI 호환 API) 지원 — API 키·비용 없이 기관 GPU에서 구동, 데이터 외부 유출 없음
- 백엔드 추상화: `--backend anthropic|ollama` (감독/학생 모델 독립 설정)
- 기관 배포 가이드, 사용자 매뉴얼, 개인정보 정책 문서화
- (선택) 커스텀 GPT / Claude Project 간이판 — 설치 없이 구독만으로 쓰는 축소 버전

## 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| 비용 폭발 (턴마다 다중 호출) | 감독 패턴(턴당 ≤4회), 프롬프트 캐싱, 전사 요약, 감독은 Haiku |
| 페르소나 붕괴 (긴 세션에서 캐릭터가 흐려짐) | 상태 게이지를 명시적 수치로 강제, 발화 시 페르소나 전문 재제공(캐시), 감독이 일관성 감시 |
| 지나치게 착한 학생들 (AI가 갈등·무기력을 미화) | 감독 프롬프트에 "미화 금지" 명시, 상태 게이지가 낮으면 부정 반응을 강제 |
| 교사가 시뮬레이션을 실제 학생 예측으로 오신 | 모든 화면·리포트에 시뮬레이션 고지 유지, 평가·선발 사용 금지 명시 |
| 실제 학생 정보 입력 | 입력 UI에 익명화 안내, 가상 페르소나 생성 기능을 기본 경로로 |
