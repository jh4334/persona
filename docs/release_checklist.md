## 2. 남은 리스크

정도 순. ⛔=출시 전 해결 권장, ⚠️=운영하며 관리 가능.

- ⛔ **세션이 메모리에만 있다.** 서버 프로세스가 재시작되면 진행 중이던 모든 수업이 사라진다(리포트는 종료 시에만 저장됨). 단일 교사·로컬 실행에서는 괜찮지만, 공용 서버로 올리려면 세션 영속화(주기적 스냅샷 또는 DB)가 필요하다. v0.6(ChatGPT App + Supabase) 설계가 이 문제의 해답이기도 하다.
- ⛔ **인증이 없다.** 지금은 URL을 아는 누구나 세션을 만들 수 있다. 같은 Wi-Fi 안에서 쓰는 전제로는 허용 가능하나, 공개 인터넷에 올리면 안 된다(세션 상한 30개가 유일한 방어). 공개 배포 전 로그인(v0.6의 Sign in with ChatGPT 또는 간단한 액세스 코드)이 필요하다.
- ⚠️ **codex 백엔드 지연.** 턴당 수십 초가 걸릴 수 있고 타임아웃(320초)까지 버티는 동안 교사는 기다려야 한다. 경과초 표시·안내 문구로 완화했지만, 근본 개선은 스트리밍 응답 또는 v0.6 구조(클라이언트 쪽 모델 실행)다.
- ⚠️ **anthropic 백엔드 과금 상한 없음.** 서버 쪽에서 세션당 호출 수를 세지 않는다. 교사 개인 키 사용 전제라 두었지만, 운영 서비스라면 세션당 턴 수 상한(예: 200턴)을 넣는 것이 안전하다.
- ⚠️ **감독·학생 품질은 모델 의존.** 페르소나 일관성은 프롬프트로 유도할 뿐 보장되지 않는다(MatrAIx 논문 기준으로도 91.5%). "시뮬레이션은 예측일 뿐"이라는 고지 문구를 화면에 유지할 것.
- ⚠️ **모바일 사파리 미검증.** Playwright(크로미엄)로만 자동 검증했다. iOS 사파리에서 바텀시트·safe-area·키보드 동작은 실기기 확인이 필요하다.

## 3. 배포 전 체크리스트

**환경**
- [ ] Python 3.11+, `pip install -r requirements.txt`
- [ ] (codex) 서버 PC에서 `codex login` 완료, `codex exec` 단독 실행 확인
- [ ] (anthropic) `ANTHROPIC_API_KEY` 설정, 소액 한도 걸린 키인지 확인
- [ ] `reports/` 디렉터리 쓰기 권한 (리포트 자동 저장 위치)

**기동 확인**
- [ ] `PYTHONPATH=src python -m classroom_sim.web --port 8000` 기동, 터미널에 로그 포맷(`HH:MM:SS INFO ...`) 출력 확인
- [ ] `curl http://127.0.0.1:8000/healthz` → `{"status":"ok", ...}`
- [ ] 휴대폰 사용 시 `--host 0.0.0.0`으로 띄우고 기동 배너의 LAN 주소로 접속 확인

**보안·데이터**
- [ ] 공개 인터넷에 직접 노출하지 않는다 (인증 없음 — LAN 또는 터널 + 접근 제한)
- [ ] 학급 JSON에 실제 학생 개인정보(실명·진단명·가정사)가 없는지 확인
- [ ] 평가·선발 목적 사용 금지 고지가 셋업 화면에 보이는지 확인

**기능 스모크 (5분)**
- [ ] mock 백엔드로 수업 시작 → 전체 발화 1회 → 학생 반응·게이지 변화 확인
- [ ] `@` 입력 → 자동완성 목록 → 지목 1회
- [ ] `/판서 3:5` → 칠판에 글씨 표시
- [ ] 새로고침 → 이어하기 배너 → 복구 확인
- [ ] `/종료` → 확인 다이얼로그 → 리포트 화면 + `reports/stage/`에 md·전사 JSON 생성 확인
- [ ] `tests/regression/` 전체 실행: `cd tests/regression && for t in test_cycle*.py; do python $t; done`

## 4. 테스트 시나리오

`tests/regression/`의 자동화 시나리오 (Playwright는 크로미엄 필요, `PLAYWRIGHT_CHROMIUM` 환경변수로 경로 지정 가능):

| `test_cycle5.py` | 턴 후 캔버스 렌더링, 유휴 프레임 스킵(초당 ≤10회), 전사 DOM 400줄 상한, 배치 스크롤, 재시작 후 렌더링 |
| `test_cycle6.py` | @자동완성 필터·클릭·키보드 선택, /도움말 로컬 처리, 오타 명령·없는 학생 사전 차단, 정상 지목 전송 |
| `test_cycle7.py` | 감독 LLM 쓰레기 출력 6종 방어, 게이지 범위·국면·시간 점프 방지, 학생 발화 비정상 형식 침묵 폴백, /시간 예외, 정상 흐름 회귀 |

| `test_cycle9.py` | /healthz 응답·세션 수, 생성/턴 소요시간/리포트 저장/턴 실패 로그 |
| `test_cycle10.py` | 백엔드 설명 전환, mock 모드 안내, 첫 실행 길잡이 1회 제한 |

**수동 시나리오 (자동화 밖):**

1. **실백엔드 리허설**: codex 백엔드로 10분 수업 1회 — 턴당 대기 시간이 수업 흐름을 깨지 않는지, 학생 발화가 페르소나와 맞는지 (`docs/rehearsal_guide.md` 참조).
2. **동시 사용자**: 브라우저 2개로 각각 수업 생성 — 서로 간섭 없는지, 한쪽에서 연타 시 409 안내가 자연스러운지.
3. **모바일 실기기**: 폰에서 접속 — 바텀시트, 명령바 가로 스크롤, 키보드 위 입력줄, 가로 회전.
4. **장시간 수업**: 40턴 이상 진행 — 전사 접힘 안내 표시, 폰 발열·입력 지연 없는지.
5. **서버 재시작 복구 한계 확인**: 수업 중 서버 재시작 → 이어하기가 "복원하지 못했습니다"를 명확히 안내하는지 (알려진 한계, §2 참조).
