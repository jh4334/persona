# v0.7 개발 과제

v0.6(클라우드 전환) 완료 시점에서 다섯 관점 — 교사 경험 · 기술 부채 · 운영 배포 ·
제품 차별성 · 보안 개인정보 — 으로 코드베이스를 훑어 나온 25건을 정리한 것.
상위 항목은 실제로 코드를 열어 확인했고, 확인되지 않은 주장은 아래 §4에 격하해 두었다.

## 요약

> **v0.6은 "여러 교사가 안전하게 쓸 수 있게" 만들었다.
> v0.7은 "교사가 자기 수업에 실제로 쓸 수 있게" 만드는 단계다.**

지금 이 도구로는 **남의 수업(비와 비율 샘플 하나)만 리허설할 수 있다.** 학급은
폼으로 만들 수 있게 됐지만 수업안은 넣을 방법이 아예 없다. 이 비대칭 하나가
"내 수업 준비에 쓴다"는 본래 목적을 막고 있다.

## 1. 먼저 (v0.7 핵심)

### 1-1. 수업안 빌더 — 학급과 대칭 맞추기 〔대〕

v0.6에서 학급은 폼·사용자별 저장·클라우드·삭제까지 갖췄는데 수업안은 그대로 남았다.

| | 폼 UI | 사용자별 저장 | Supabase | 삭제 |
|---|---|---|---|---|
| 학급 | ✓ | ✓ | ✓ | ✓ |
| **수업안** | **✗** | **✗** | **✗** | **✗** |

확인된 근거:
- `index.html` — 학급 옆에는 `btn-cls-add`가 있으나 `sel-lesson` 옆에는 아무 버튼도 없다
- `server.py` — `POST/DELETE /api/classrooms`는 있으나 수업안은 `GET /api/lessons` 하나뿐
- `lessons/` 디렉터리에 파일이 **1개**(`ratio_and_rate.md`)

만들 것: `builder.js`와 같은 2탭 구조(폼 / 마크다운 붙여넣기). 폼은 자유 텍스트가
아니라 **구조를 갖게** 한다 — 학습 목표(여러 줄), 주요 개념·용어, 수업 흐름(국면 +
계획 분 + 지시문), 예상 난점. 저장 형식은 지금의 `lessons/*.md`와 호환되게 둔다.

구조를 넣는 이유는 다음 과제 때문이다.

### 1-2. 수업안 대조 리포트 〔중〕

**리포트가 수업안을 한 번도 보지 않는다.** 확인:

```
analysis.analyze(transcript_json, classroom, backend)   ← lesson_text 인자가 없음
session.py:648 이 그대로 호출
```

그래서 리포트는 "학생들이 이랬다"까지만 말하고, "내 수업 설계의 어디가 계획과
달랐다"는 말을 못 한다. 교사가 지도안을 고칠 때 집어 쓸 수 있는 형태가 아니다.

추가할 섹션:
1. **국면별 계획 분 vs 실제 분** — 전사의 `minute`·`phase`로 결정적으로 계산 (LLM 불필요)
2. **학습 목표별 도달 여부** — 목표마다 다룸/부분/미도달 + 근거 전사 인용 1줄
3. **예상 난점 적중표** — 수업안에 적은 난점이 실제로 나타났는지

1-1이 구조화된 수업안을 만들어 주므로 이것이 가능해진다. **두 과제는 한 묶음이다.**

### 1-3. 배포 산출물과 CI 〔중〕

확인: `Dockerfile`·`compose`·`Procfile`·`.github/`·lock 파일이 **하나도 없다.**
회귀 23개 스위트가 있는데 **수동 실행에만 의존**한다.

- `Dockerfile` + `compose.yml` (Chromium 포함 테스트용 스테이지 분리)
- GitHub Actions — push마다 `run_all.py`
- `requirements.txt` 버전 고정 또는 `pyproject.toml`

지금은 "돌아가는 코드"이지 "배포할 수 있는 소프트웨어"가 아니다.

## 3. 나중 (제품을 키우는 것들)

- **개념·오개념 원장** 〔대〕 — 지금 모든 학생이 이해도 60/흥미 60/집중 70으로 똑같이
  시작한다(`session.py:69`). 페르소나를 반영한 **과목별 출발점**과 오개념 목록을
  두면 "누가 무엇을 왜 못 따라오는가"가 게이지 숫자에서 내용으로 바뀐다.
- **A/B 비교** 〔중〕 — 로드맵 v0.5 범위였으나 미착수. 같은 학급·단원을 두 설계안으로
  자동 진행해 나란히 비교. 1-2(수업안 대조)가 선행되어야 의미가 있다.
- **반복 실행과 분산** 〔중〕 — 지금은 1회 결과를 단정한다. 같은 수업을 여러 번 돌려
  "이 학생은 5회 중 4회 이해도가 떨어졌다"처럼 말하면 신뢰도가 다르다.
- **지도교수·연수 모드** 〔대〕 — RLS가 전부 `user_id = auth.uid()`라 **공유가 원천
  불가**하다. 교생 여럿의 수업을 지도교수가 보는 시나리오를 열려면 스키마부터 바꿔야 한다.
- **내 수업 성장 이력** 〔중〕 — `reports` 테이블에 지표 컬럼이 없어 회차 간 비교가 안 된다.
- **기관 제출 문서 세트** 〔중〕 — `docs/`에 개인정보 관련 문서가 **0건**. 학교 도입 시 필요.
- **내 데이터 완전 삭제** 〔중〕 — 교사가 자기 데이터를 한 번에 지울 방법이 없다.
  리포트는 디스크에도 늘 남고 보존 기간 정책이 없다.
- **가명 입력 게이트** 〔중〕 — 실명 입력을 막는 장치가 고지문뿐이다. 학급 만들기 폼에는
  경고조차 없다.

## 4. 격하하거나 제외한 것

| 제기된 것 | 판단 |
|---|---|
| 학급 id 경로 탈출 취약점 | **재현되지 않음.** `cid`에 `../`를 넣어 직접 시도했으나 저장소 밖에 파일이 생기지 않았다. 다만 PostgREST 쿼리에 `cid`를 검증 없이 보간하는 것은 사실이고(샘플 쪽은 `re.fullmatch`로 막는다), **방어적 강화** 수준으로 2-3에 흡수 |
| `dev_fake.py` 유령 구현 493줄 | 개발 편의 코드. 실제 동작에 영향 없어 우선순위 낮음 |
| 동시 세션 30개 상한 | 의도된 보호 장치. 늘리려면 근거(실측)가 먼저 필요 |
| 이벤트 루프 블로킹 | 실측 없이 지적됨. 2-1(병렬화) 때 함께 측정할 것 |

## 5. 권하는 순서

**1-1 → 1-2를 한 묶음으로 먼저.** 이 둘이 "남의 수업 구경"과 "내 수업 준비"를
가르는 선이다. 나머지는 전부 이 선을 넘은 뒤에 의미가 커진다.

그다음 **1-3(배포·CI)** — 회귀 23개를 자동으로 돌리지 않으면 앞으로의 변경이
위험해진다.

2번대는 실제로 배포해 써 보면서 아픈 순서대로. 특히 2-2(백엔드 실패 침묵)는
크기가 작은데 첫 사용자를 잃기 쉬운 지점이다.
