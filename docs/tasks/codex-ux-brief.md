# 작업 지시서 — 실사용 관점 UX 개편

> **수신**: Codex  ·  **대상 저장소**: `jh4334/persona` (보이는 교실)
> **기준 커밋**: `f1b6a4e` (v0.6 + Vercel 배포 완료, 회귀 27/27 통과)

## 0. 이 작업의 배경

기능은 다 만들어졌는데 **손이 안 간다.** 만든 사람 본인이 "어디로 들어가도 뭘
어떻게 조작해야 하는지 모르겠다"고 느끼는 상태다.

원인은 코드 품질이 아니라 **경로 설계**다. 지금 교사가 무언가를 얻으려면
`실시간 40분 수업 진행`이라는 단 하나의, 가장 비싼 경로밖에 없다.

| 교사가 하고 싶은 것 | 지금 드는 비용 | 목표 |
|---|---|---|
| "이 주제 던지면 우리 반이 어떻게 반응하지?" | 1시간+ | **10초** |
| "내일 이 수업, 어디서 막힐까?" | 1시간+ | 3분 |
| 수업 진행 연습 | 40분 | 40분 (유지) |

아래 세 과제는 앞의 두 줄을 채우는 일이다. 상세 진단은
[`docs/why-low-usage.md`](../why-low-usage.md) 참조.

**작업 순서는 2 → 3 → 1 을 권한다.** 2번이 새 경로를 만들고, 3번이 그 경로에
넣을 재료를 만들고, 1번이 전체를 다시 배치하는 순서다. 1번을 먼저 하면 곧
2·3번 때문에 다시 고쳐야 한다.

# 과제 1. UI/UX — 첫 화면에서 무엇을 할지 알게 하기

## 지금 무엇이 문제인가 (확인된 사실)

**셋업 화면 하나에 컨트롤이 24개다.** `src/classroom_sim/web/static/index.html`
의 `#screen-setup` 안에 학급 선택·학급 빌더 전체(2탭, 학생 카드, 속성 9그룹,
인원 일괄 생성 패널)·수업안 선택·백엔드 선택·시작 버튼·이어하기 배너·계정이
전부 한 상자에 들어 있다.

구체적으로:

1. **교사에게 백엔드를 고르라고 묻는다.** `<select id="sel-backend">`에
   `mock / codex / anthropic`이 그대로 노출된다. 교사는 이 셋의 차이를 모르고,
   알 이유도 없다. 게다가 Vercel 배포에서는 `codex`가 아예 동작하지 않는다
   (`ALLOWED_BACKENDS`가 서버리스에서 제외한다).
2. **학급 빌더가 셋업 박스 안에 인라인으로 펼쳐진다.** 학급을 만드는 동안
   "수업 시작" 버튼이 함께 보여, 지금이 무슨 작업 중인지 흐려진다.
3. **누르기 전까지 무엇이 일어날지 모른다.** [수업 시작]을 누르면 40분짜리
   실시간 진행으로 들어가는데, 그 사실이 화면에 없다.
4. **무대 화면은 명령어를 외워야 한다.** `/판서 /활동 /모둠 /순회 /칭찬 /주의
   /시간 /돌발 /상태` — 버튼이 있지만 무엇을 언제 쓰는지는 알려 주지 않는다.

## 무엇을 만들 것인가

### 1-1. 첫 화면을 "무엇을 하고 싶은가" 3장의 카드로

셋업 화면을 목적 선택으로 바꾼다. 학급·수업안·백엔드를 먼저 묻지 않는다.

```
┌─────────────────────────────────────────────┐
│  보이는 교실                                 │
│  학생 페르소나를 무대로 데려와 수업합니다      │
├─────────────────────────────────────────────┤
│  ⚡ 반응 먼저 보기                    10초   │
│     주제 하나 던져 보고 아이들 반응만 확인    │
│                                              │
│  📋 수업 리허설                        3분   │
│     수업안 전체를 자동으로 돌려 리포트 받기   │
│                                              │
│  🎓 직접 진행하기                     40분   │
│     내가 한 마디씩 진행하는 실시간 수업       │
└─────────────────────────────────────────────┘
```

- **첫 칸(반응 먼저 보기)이 과제 2다.** 지금 없는 기능이므로 과제 2를 먼저 해야
  이 카드가 산다.
- 두 번째 칸(리허설)은 아직 없다 — 이번 범위 밖이면 **버튼을 비활성 + "준비 중"**
  으로 두고, 카드 자리는 미리 잡아 둔다.
- 세 번째 칸이 지금의 셋업 화면이다.

각 카드에 **소요 시간을 표시**하는 것이 핵심이다. 교사가 "지금 10초짜리를
할지 40분짜리를 할지" 고르게 만든다.

### 1-2. 백엔드 선택을 화면에서 없앤다

교사에게 묻지 말고 서버가 정한다.

- `GET /api/auth/config` 또는 `/healthz`가 이미 `backends` 목록을 준다.
  프런트가 **우선순위대로 자동 선택**한다: `anthropic` → `codex` → `mock`
  (사용 가능한 것 중 첫 번째).
- 화면에는 결과만 한 줄로 보여 준다:
  `AI 반응 사용 중` / `연습 모드 — 규칙 기반 반응입니다`
- 바꾸고 싶은 사람을 위해 **[고급] 접기** 안에만 남긴다.
- `mock`이 선택됐을 때는 **연습 모드임을 화면에서 계속 보이게** 한다. 지금은
  가짜 반응을 진짜로 오해할 여지가 있다.

### 1-3. 학급 빌더를 전용 화면으로 분리

`#cls-editor`를 셋업 박스 안 인라인에서 **전체 화면 또는 모달**로 뺀다.
`body[data-screen="classroom"]`을 하나 더 두면 기존 화면 전환 방식과 맞는다
(`style.css`의 `body[data-screen=...]` 규칙 참조).

- 빌더가 열려 있는 동안 [수업 시작]은 보이지 않아야 한다
- 저장하면 원래 화면으로 돌아가고 방금 만든 학급이 선택돼 있어야 한다
  (지금 동작 유지 — `UI.saveClassroom`)

### 1-4. 무대 화면에 "지금 할 수 있는 것"

명령어를 외우게 하지 말고 상황에 맞춰 제안한다.

- 수업 시작 직후: `학생들에게 첫 마디를 건네 보세요` + 예시 문장 2개를 칩으로
- 5턴 이상 같은 국면: `활동으로 넘어가 볼까요? [/활동]`
- 특정 학생 게이지가 낮게 유지: `최민준이 계속 흐트러져 있어요 [@최민준] [/순회 최민준]`
- 칩을 누르면 입력창에 채워지고 커서가 뒤에 놓인다 (`insertCommand()` 재사용)

규칙 기반으로 충분하다. LLM을 부르지 않는다.

## 받아들임 기준

- [ ] 처음 접속한 사람이 **아무 설명 없이** 첫 화면에서 무엇을 할지 고를 수 있다
- [ ] 백엔드 select가 기본 화면에 없다. `mock`일 때 "연습 모드"가 계속 보인다
- [ ] 학급 빌더가 열린 동안 수업 시작 버튼이 보이지 않는다
- [ ] 무대에서 첫 턴 전에 예시 문장 칩이 보이고, 누르면 입력창에 들어간다
- [ ] `python tests/regression/run_all.py` → ALL REGRESSION PASS
- [ ] 새 Playwright 스위트 `tests/regression/test_cycle29.py` 추가

# 과제 2. 추천 키워드 → 반응 즉시 보기 ★ 최우선

## 원하는 것

수업 주제를 **길게 쓰지 않는다.** 가볍게 클릭하면 추천 키워드가 뜨고, 누르면
아이들이 어떻게 반응하는지 바로 보인다.

```
학급: 6학년 3반 ▼

무엇을 해 볼까요?
 [비와 비율]  [분수의 나눗셈]  [토론 수업]  [모둠 활동]  [갑자기 조용해질 때]
 [어려운 질문 던지기]  [칭찬하기]  [딴짓하는 학생]        ↻ 다른 주제

  ↓ 누르면

💬 김하늘  "3 대 5랑 5 대 3이랑 같은 거예요?"     이해도 ▲
💬 최민준  (고개를 숙이고 연필만 굴린다)          집중 ▼
💬 강도윤  "선생님 그거 학원에서 배웠어요!"        흥미 ▲

              [다른 주제 보기]  [이 주제로 수업 시작하기]
```

**세션을 만들지 않는다.** 한 번 던져 보고 반응만 본다. 마음에 들면 그때
수업으로 넘어간다.

## 만들 것

### 2-1. `GET /api/topics`

학급을 보고 추천 키워드를 돌려준다. **LLM을 부르지 않는다** — 학년·교과·학생
구성에서 규칙으로 만든다.

```jsonc
// GET /api/topics?classroom_id=sample:class_6_3
{
  "groups": [
    { "label": "교과 주제", "items": ["비와 비율", "분수의 나눗셈", "소수의 곱셈"] },
    { "label": "수업 방식", "items": ["토론 수업", "모둠 활동", "짝 활동"] },
    { "label": "교실 상황", "items": ["갑자기 조용해질 때", "딴짓하는 학생",
                                      "어려운 질문 던지기", "칭찬하기"] }
  ]
}
```

- 교과 주제는 학급의 `grade` 필드로 고른다. 초등 학년별 단원 목록을
  `src/classroom_sim/topics.py`에 상수로 둔다 (외부 호출 없음)
- 수업 방식·교실 상황은 학년과 무관한 고정 목록
- `grade`가 비었거나 모르는 값이면 **공통 목록만** 돌려준다 (빈 배열 금지)
- `↻ 다른 주제`는 같은 풀에서 다시 뽑는다 (프런트에서 셔플)

### 2-2. `POST /api/probe`

한 마디를 던지고 반응만 받는다. **세션을 만들지 않고, 저장하지 않는다.**

```jsonc
// 요청
{ "classroom_id": "sample:class_6_3", "prompt": "비와 비율" }

// 응답
{
  "prompt": "비와 비율",
  "reactions": [
    { "student_id": "S01", "name": "김하늘",
      "utterance": "3 대 5랑 5 대 3이랑 같은 거예요?", "action": "",
      "deltas": { "comprehension": 5, "interest": 10, "focus": 0 } },
    { "student_id": "S04", "name": "최민준",
      "utterance": "", "action": "고개를 숙이고 연필만 굴린다",
      "deltas": { "comprehension": -5, "interest": -5, "focus": -10 } }
  ],
  "backend": "mock"          // 어떤 백엔드로 만든 반응인지 (연습 모드 표시용)
}
```

구현:
- `StageSession`을 **메모리에만** 하나 만들고 `turn(prompt)` 1회 → 결과만 추출 →
  버린다. 스냅샷 저장·리포트 저장을 하지 않는다
- 키워드만 넘어오면(`"비와 비율"`) 그대로 교사 발화로 쓰지 말고
  **자연스러운 문장으로 감싼다**: `"오늘은 비와 비율을 배워 볼 거예요."`
  교실 상황 키워드(`딴짓하는 학생`)는 상황 지시로 바꾼다. 매핑을
  `topics.py`에 함께 둔다
- **비용 방어**: `/api/probe`에 사용자당 속도 제한을 건다. 기존
  `_check_create_rate`와 같은 방식으로 별도 카운터(예: 10분당 30회)
- 반응은 최대 3명

### 2-3. 프런트

첫 화면 카드 [⚡ 반응 먼저 보기]에서 들어간다.

- 학급 선택(기본값: 첫 번째 학급) → 키워드 칩 → 클릭 → 로딩 → 반응 3개
- **로딩 중에도 무엇을 기다리는지 보인다**: `아이들이 생각하는 중...`
- 게이지 변화는 화살표만(▲▼) — 숫자를 보여 주지 않는다. 이 화면은 "느낌"을
  보는 곳이다
- 하단 [이 주제로 수업 시작하기] → 그 키워드를 첫 발화로 넣고 실시간 무대로
- 직접 입력란도 둔다 (칩이 마음에 안 들 때)

## 받아들임 기준

- [ ] 로그인 후 **클릭 3번 안에** 학생 반응을 볼 수 있다 (카드 → 칩 → 결과)
- [ ] `/api/probe`가 세션을 만들지 않는다 — 호출 후 `/healthz`의 `sessions`가 늘지 않는다
- [ ] `/api/probe`가 스냅샷·리포트를 저장하지 않는다 (Supabase 행이 늘지 않음)
- [ ] `grade`가 없는 학급도 키워드가 비어 있지 않다
- [ ] 속도 제한이 동작한다 (초과 시 429 + 한국어 안내)
- [ ] `mock` 백엔드일 때 "연습 모드" 표시가 결과 화면에 보인다
- [ ] 새 스위트 `tests/regression/test_cycle30.py`

# 과제 3. 페르소나 커스터마이징 — "고정돼 있다"는 느낌 없애기

## 지금 무엇이 문제인가 (확인된 사실)

1. **샘플 학급을 고칠 수 없다.** `SampleClassrooms`는 읽기 전용이고
   (`src/classroom_sim/web/classrooms.py`), 복제 기능도 없다. 12명짜리 샘플이
   마음에 안 들면 **처음부터 다시 만들어야** 한다.
2. **자동 생성이 없다.** 폼의 [인원 한 번에 만들기]는 `builder.js`의
   `quickFill()`인데 **이름과 성취 수준만** 채운다 (`학생01`, `중`). 나머지
   사전 지식·학습 스타일·흥미·성격·교우 관계는 전부 빈칸이다.
   12명 × 기본 7칸 = **84칸을 손으로** 채워야 한다.
3. **수업 중에 학생을 못 고친다.** 무대에서 학생 카드를 열어도 조회만 된다.
   "얘는 좀 더 소극적이었으면" 싶어도 방법이 없다.

이 셋이 합쳐져서 "페르소나가 고정돼 있고, 뭘 해도 안 바뀌는 것처럼" 느껴진다.

## 만들 것

### 3-1. 샘플 학급 복제 → 내 학급

학급 선택 옆에 **[이 학급 복제해서 수정]**. 누르면 샘플 내용이 그대로 담긴
내 학급이 만들어지고 빌더가 열린다.

- 서버: `POST /api/classrooms/{id}/duplicate` — `LIBRARY.resolve()`로 원본을
  읽어 `LIBRARY.create()`로 저장. 이름 뒤에 ` (사본)`
- 내 학급끼리도 복제 가능하게 (같은 엔드포인트)
- **이것 하나로 "고정" 느낌의 절반이 사라진다.** 가장 작은 작업이므로 먼저.

### 3-2. 학급 자동 생성 — 84칸을 0칸으로

`quickFill()`을 실제로 쓸 만하게 만든다. 성취 수준별 인원만 넣으면
**전 항목이 채워진 초안**이 나와야 한다.

```
6학년 25명 · 상 5 · 중상 5 · 중 8 · 중하 4 · 하 3
                    ↓ [만들기]
25명이 이름·성격·흥미·학습 스타일까지 채워진 채로 생성
```

구현 방침 — **LLM 없이 규칙으로 만든다** (즉시 응답, 비용 0, 서버리스 안전):

- `src/classroom_sim/personas_gen.py` 신설
- 이름 풀: 성 + 이름 조합에서 중복 없이 뽑기
- 성취 수준별로 **어울리는 값의 풀**을 두고 뽑는다. 예를 들어 성취 '하'인
  학생에게는 `사전 지식: "기초 연산에서 자주 막힘"`, `학습 스타일: "한 단계씩
  짚어 주면 따라옴"` 같은 것이 나오게 한다
- 흥미는 초등 관심사 풀에서 1~2개
- 속성 그룹(9그룹 102속성)도 성취 수준과 어긋나지 않게 몇 개만 채운다
  (`personas/schema/dimensions.json`의 `values` 안에서만 고를 것)
- **같은 조합이면 같은 결과가 나오지 않게** 한다 (seed를 매번 다르게)
- 다양성 보장: 같은 성취 수준 안에서도 성격·흥미가 겹치지 않게

프리셋도 함께 둔다 — [활발한 학급] [조용한 학급] [편차가 큰 학급].
누르면 인원 분포와 성격 풀이 한 번에 세팅된다.

### 3-3. 수업 중 학생 편집

무대 화면 학생 카드(`#dc-*`)에 **[이 학생 조정]**을 넣는다.

- 게이지 3개(이해도·흥미·집중)를 슬라이더로 직접 조정
- 정서·현재 행동을 텍스트로 수정
- 서버: `PATCH /api/sessions/{sid}/students/{student_id}`
  → `session.state.students[sid]` 갱신 + `_persist_session()`
- 값은 `clamp()`로 0~100 유지 (`stage/state.py`)
- 전사에 `무대 / narration`으로 남긴다: `[교사 조정] 최민준의 집중을 30으로 바꿨습니다`
  — 리포트에서 "이건 시뮬레이션이 아니라 내가 바꾼 것"이 구분돼야 한다

**주의**: 이 편집은 진행 중 세션의 상태만 바꾼다. 원본 학급(`classrooms` 테이블)은
건드리지 않는다. 다음 수업에도 반영하고 싶으면 별도로 학급을 고쳐야 한다 —
이 사실을 화면에 한 줄로 알려 줄 것.

## 받아들임 기준

- [ ] 샘플 학급을 복제해 바로 수정할 수 있다
- [ ] [인원 한 번에 만들기]로 만든 학생이 **빈칸 없이** 채워져 있다
- [ ] 같은 설정으로 두 번 만들면 서로 다른 학생들이 나온다
- [ ] 성취 '하'인 학생에게 "선행학습으로 앞서감" 같은 모순된 값이 나오지 않는다
- [ ] 수업 중 학생 게이지를 조정할 수 있고, 조정 사실이 전사에 남는다
- [ ] 학급 자동 생성이 LLM을 호출하지 않는다 (오프라인에서도 동작)
- [ ] 새 스위트 `tests/regression/test_cycle31.py`
