# 왜 활용도가 아쉬운가 — 진단과 처방

배포까지 마친 시점에서 "쓸 만하지 않다"는 느낌의 원인을 코드로 확인해 정리한 것.

## 한 줄 진단

> **비용 사다리에 가장 비싼 칸 하나만 있다.**

교사가 이 도구에서 무언가를 얻으려면 지금은 **실시간 40분 수업 진행**이라는
단 하나의 경로밖에 없다. 그런데 교사가 실제로 자주 하고 싶은 일은 그보다
훨씬 싼 것들이다.

| 교사가 하고 싶은 것 | 지금 드는 비용 | 있어야 할 비용 |
|---|---|---|
| "내일 이 수업, 우리 반 어디서 막힐까?" | 1시간+ | **3~5분** |
| "이 학생은 이 활동에서 어떨까?" | 1시간+ | **1분** |
| 수업 진행 자체를 연습 | 40분 | 40분 (이건 맞다) |

앞의 두 줄이 비어 있다. 그래서 "한 번 해 보고 다시 안 쓰게" 된다.

## 1시간이 어디서 나오나 (확인된 것)

```
로그인            메일 대기 1~2분
학급 만들기       12명 × 기본 7칸 = 84칸을 손으로   ← 자동 생성 없음(확인)
수업안 선택       샘플 1개뿐, 내 수업은 못 넣음      ← 빌더·API 없음(확인)
수업 진행         40분 수업안을 수십 번 타이핑        ← 자동 진행 없음(확인)
                  턴마다 수십 초 대기
리포트            수업안을 한 번도 안 봄              ← analyze()에 lesson_text 없음(확인)
```

## 정작 값싼 경로는 이미 만들어 놓고 안 쓰고 있다

**v0.1의 일괄 예측 리포트**가 정확히 "3~5분 경로"다. 수업안 + 학급을 넣으면
학생별 예상 반응·질문·오개념·난점과 지도 전략이 한 번에 나온다. 호출 13회,
README 기준 수백 원~수천 원.

그런데 **웹 어디에도 노출돼 있지 않다.** `simulate_classroom`이 웹 코드에
한 번도 등장하지 않는다 — CLI 전용이다. 교사는 CLI를 쓰지 않는다.

## 왜 이렇게 됐나

로드맵이 **기능 축**(터미널판 → 웹 UI → 살아있는 교실 → 클라우드)을 따라갔다.
그 축에서는 실시간 무대가 종착점이고, 실제로 잘 만들어졌다.

문제는 **교사의 용도 축**에서 실시간 진행이 가장 비싼 선택지라는 점이다.
가장 비싼 것만 완성해 두면, 잘 만들어져 있어도 손이 안 간다.

## 배포한 지금, 무료로 진짜 반응을 볼 수 있는 경로는 하나뿐이다

Vercel에 올린 상태에서 백엔드별 실상:

| 백엔드 | 웹 UI에서 | 실제 의미 |
|---|---|---|
| `mock` | ✅ 동작 | **가짜 반응**. 화면 익히기용 |
| `anthropic` | ✅ 동작 | 진짜지만 **API 과금** |
| `codex` | ❌ 불가 | 서버리스가 하위 프로세스를 못 띄움 |

즉 **웹 UI만 쓰면 "무료로 진짜"가 없다.**

유일한 예외가 **ChatGPT MCP 경로**다. ChatGPT가 감독과 배우를 맡으므로 교사의
구독 안에서 진짜 반응이 나오고 서버 비용은 0이다. 코덱스가 OAuth까지 붙여
연결도 쉬워졌다.

그런데 이 경로에는 **도트 교실 화면이 없다.** 이 프로젝트에서 가장 눈에 띄는
자산이 정작 무료·진짜 경로에서는 안 보인다.

# 처방 — 순서대로

## 1. 빠른 리허설 (자동 진행) 〔중〕 ★ 최우선

수업안 + 학급 → **[빠른 리허설]** → AI가 교사 역할까지 대행해 40분을 자동
진행 → 리포트. 교사는 3분 기다린다.

- 엔진은 이미 있다. 없는 것은 "교사 발화를 수업안에서 만들어 내는 것" 하나
- 중간에 멈춰 "여기서부터 내가" 하면 지금의 실시간 모드로 이어진다
- 로드맵의 **A/B 비교**가 이 위에서 거의 공짜로 나온다 (같은 학급에 수업안
  둘을 자동 진행해 나란히 비교)

**이것 하나가 비용 사다리의 빈 칸을 채운다.**

## 2. 수업안 빌더 + 대조 리포트 〔대〕

1번이 있어도 넣을 수업안이 없으면 소용없다. 짝으로 간다.
리포트에 "국면별 계획 분 vs 실제 분 / 목표별 도달 / 예상 난점 적중"을 넣으면
결과가 "학생들이 이랬다"에서 "내 설계의 어디가 어긋났다"로 바뀐다.

## 3. 일괄 예측 리포트를 웹에 노출 〔소〕 ★ 가성비 최고

**이미 있는 코드에 버튼 하나.** `simulate_classroom`을 `/api/predict`로 감싸고
셋업 화면에 [수업 전 예측] 을 놓는다. 가장 작은 작업으로 가장 빠른 가치가 나온다.

셋이 합쳐지면 교사의 선택지가 이렇게 된다:

```
[수업 전 예측]   1분   — 학생별 예상 반응·오개념        (3번)
[빠른 리허설]    3분   — 40분 자동 진행 + 대조 리포트   (1번)
[직접 진행]     40분   — 지금의 실시간 무대             (이미 있음)
```

## 4. 학급 자동 생성 〔중〕

"6학년 25명, 성취 상5 중15 하5, 다문화 1명" → 페르소나 초안 자동 생성.
지금은 84칸을 손으로 채운다. 로드맵 v0.4에 있었으나 미착수.
폼의 [인원 한 번에 만들기]가 이름과 성취 수준만 채우는데, 여기에 살을 붙이면 된다.

## 5. ChatGPT 경로에 교실 화면 〔중〕

지금 유일한 "무료 + 진짜" 경로인데 표만 나온다. Apps SDK 컴포넌트로 도트 교실을
띄우면 이 프로젝트의 시각적 자산이 그 경로에서도 산다.

---

## 무엇을 하지 말아야 하나

- **실시간 무대를 더 다듬는 것.** 이미 충분히 좋다. 문제는 품질이 아니라
  그 경로가 너무 비싸다는 것이다.
- **기술 부채 정리를 먼저 하는 것.** server.py 817줄·app.js 2042줄은 사실이지만,
  아무도 안 쓰는 코드를 깔끔하게 만드는 일이다. 1~3번 뒤로.
