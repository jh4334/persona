### v0.6 — 클라우드 전환 (1차 결산의 ⛔ 두 건을 제거)

| # | 주제 | 반영 내용 |
|---|---|---|
| 1 | 세션 저장소 추상화 | 스냅샷을 디스크와 Supabase에 이중 기록, 복구 시 더 최근 것 우선 — 서버를 갈아끼워도 수업이 살아남는다 |
| 2 | 로그인 | Supabase Auth 이메일 인증(링크 + 6자리 코드), 세션 소유권 검사, 사용자별 생성 제한 |

두 기능 모두 **환경변수를 설정할 때만 켜진다.** 설정하지 않으면 기존 동작(로그인 없음 · 디스크 저장)이 그대로 유지되므로, 같은 Wi-Fi 안에서 쓰던 방식은 달라지지 않는다.

모든 회차는 자동화 테스트(Playwright E2E 또는 단위 테스트)로 검증 후 커밋했다. 테스트는 `tests/regression/`에 있고, `python tests/regression/run_all.py`로 일괄 실행한다.

## 2. 남은 리스크

정도 순. ⛔=출시 전 해결 권장, ⚠️=운영하며 관리 가능. (~~취소선~~은 2차 라운드에서 해결된 항목)

- ~~⛔ 인증이 없다~~ → **v0.6-2에서 해결** (Supabase Auth 이메일 로그인). `SUPABASE_URL`/`ANON_KEY`를 설정하면 자동으로 켜지고, 로그인한 교사만 수업을 만들 수 있으며 남의 수업은 404로 숨긴다. 설정하지 않으면 기존처럼 열린 상태로 동작하므로 **공개 배포 시에는 반드시 켤 것**. 절차는 [docs/supabase_setup.md](supabase_setup.md).
- ⚠️ **로그인 메일 발송 한도.** Supabase 기본 발송기는 시간당 2~3통짜리 테스트용이다. 여러 교사가 쓰려면 직접 쓰는 SMTP를 연결해야 한다.
- ~~⛔ 세션이 메모리에만 있다~~ → **11차에서 해결** (턴마다 디스크 스냅샷 + 기동 시 복구). ~~단, 단일 서버 디스크 기준이라 다중 서버·컨테이너 재배포에는 부족~~ → **v0.6-1에서 해결** (`SUPABASE_URL`/`KEY` 설정 시 디스크와 Supabase 이중 기록, 디스크 없이도 복구). 설정하지 않으면 기존대로 디스크만 쓴다. 절차는 [docs/supabase_setup.md](supabase_setup.md).
- ⚠️ **codex 백엔드 지연.** 턴당 수십 초는 여전하다. 12차의 턴 예산으로 "몇 분씩 잠기는" 최악 상황은 제거했지만, 근본 개선은 스트리밍 응답 또는 v0.6 구조(클라이언트 쪽 모델 실행)다.
- ~~⚠️ anthropic 과금 상한 없음~~ → **13차에서 해결** (세션당 200턴 상한 + 생성 속도 제한).
- ⚠️ **감독·학생 품질은 모델 의존.** 페르소나 일관성은 프롬프트로 유도할 뿐 보장되지 않는다(MatrAIx 논문 기준으로도 91.5%). "시뮬레이션은 예측일 뿐"이라는 고지 문구를 화면에 유지할 것.
- ⚠️ **모바일 사파리 미검증.** Playwright(크로미엄)로만 자동 검증했다. iOS 사파리에서 바텀시트·safe-area·키보드·홈 화면 추가 동작은 실기기 확인이 필요하다.
- ⚠️ **스냅샷 복구는 기동 시 1회.** 기동 후 TTL(3시간)이 지난 스냅샷은 버려진다. 밤새 세워 둔 수업을 다음 날 잇는 시나리오는 지원하지 않는 것이 의도된 동작이다.

## 3. 배포 전 체크리스트

**환경**
- [ ] Python 3.11+, `pip install -r requirements.txt`
- [ ] (codex) 서버 PC에서 `codex login` 완료, `codex exec` 단독 실행 확인
- [ ] (anthropic) `ANTHROPIC_API_KEY` 설정, 소액 한도 걸린 키인지 확인
- [ ] `reports/` 디렉터리 쓰기 권한 (리포트 자동 저장 위치)
- [ ] (다중 서버·컨테이너 재배포 시) Supabase 스키마 적용 + `SUPABASE_URL`/`SUPABASE_SERVICE_ROLE_KEY` 설정 — [docs/supabase_setup.md](supabase_setup.md)

**기동 확인**
- [ ] `PYTHONPATH=src python -m classroom_sim.web --port 8000` 기동, 터미널에 로그 포맷(`HH:MM:SS INFO ...`) 출력 확인
- [ ] `curl http://127.0.0.1:8000/healthz` → `{"status":"ok", ...}` (Supabase를 붙였다면 `"store":"disk+supabase"` 확인)
- [ ] 휴대폰 사용 시 `--host 0.0.0.0`으로 띄우고 기동 배너의 LAN 주소로 접속 확인

**보안·데이터**
- [ ] 공개 인터넷에 노출한다면 **인증을 켠다** — `/healthz`가 `"auth":"required"` 인지 확인 (v0.6-2)
- [ ] (인증 사용 시) Redirect URLs 등록 + SMTP 연결 확인 — 안 하면 로그인 메일이 오지 않거나 링크가 앱으로 돌아오지 않는다
- [ ] 학급 JSON에 실제 학생 개인정보(실명·진단명·가정사)가 없는지 확인
- [ ] 평가·선발 목적 사용 금지 고지가 셋업 화면에 보이는지 확인

**기능 스모크 (5분)**
- [ ] mock 백엔드로 수업 시작 → 전체 발화 1회 → 학생 반응·게이지 변화 확인

- [ ] `/판서 3:5` → 칠판에 글씨 표시
- [ ] 새로고침 → 이어하기 배너 → 복구 확인

1. **실백엔드 리허설**: codex 백엔드로 10분 수업 1회 — 턴당 대기 시간이 수업 흐름을 깨지 않는지, 학생 발화가 페르소나와 맞는지 (`docs/rehearsal_guide.md` 참조).

3. **모바일 실기기**: 폰에서 접속 — 바텀시트, 명령바 가로 스크롤, 키보드 위 입력줄, 가로 회전.
